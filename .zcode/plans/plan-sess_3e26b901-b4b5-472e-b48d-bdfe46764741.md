## 목표
NIED 장주기 지진동 모니터(lmoni) 실시간 GIF를 파싱해서, 지도에 장주기 계급 점 + "장주기 최대 계급" 배지를 표시한다.

## 배경 (이미 확인된 사실)
- lmoni GIF: `https://www.lmoni.bosai.go.jp/monitor/data/data/map_img/RealTimeImg/abrspmx_s/YYYYMMDD/YYYYMMDDHHMMSS.abrspmx_s.gif` — 1초 주기, **352×400으로 kmoni와 동일 캔버스** (직접 다운로드·디코딩 검증 완료)
- 주기대 8종(1s~7s, mx) 중 v1은 `abrspmx`(전 주기대 최대) 1개만 사용
- GIF 색 = 절대속도응답스펙트럼(SI, cm/s) 단계색 → 기상청 공식 기준표로 장주기 계급(0~4) 환산
- 레전드 색상표는 lmoni가 PNG로 제공 (`ScaleImg2/nied_abrsp1s_s_w_scale.png`) → 구현 시 이 이미지에서 색/경계값을 추출해 정확히 매핑 (추측 아님)
- 서버에 kmoni GIF 파싱 파이프라인(`getKmoniShindoUrl`/`fetchAndParseKmoni`/`parseIntensityMap`)이 이미 있어 복제하면 됨

## 구현 단계

### 1단계: 색상 변환표 확보 (준비)
- lmoni 레전드 PNG를 다운로드해 단계색 RGB ↔ 스펙트럼 값 표를 추출
- 스펙트럼 값 → 장주기 계급(0~4) 환산은 기상청 공식 기준표를 코드에 상수로 추가 (`src/colorMap.ts` 확장 또는 신규 `lpColorMap.ts`)

### 2단계: 서버 — lmoni 피드 추가 (server-intensity.ts)
- kmoni 파이프라인 복제: `getLmoniUrl()` + `fetchAndParseLmoni()` (같은 폴링 루프에 추가, UA/Referer 헤더 동일, source: `'lmoni'`)
- `parseIntensityMap` 재사용해 관측점 좌표(`public/intensity-points-v1.json`의 Point) 픽셀 색 샘플링
  - 1단계에서 좌표 정합성 검증: 기존 좌표로 찍은 픽셀이 실제 단계색인지 확인, 안 맞으면 lmoni 좌표 기준으로 보정
- SSE payload에 `lp: Record<code, 계급0~4|null>` 추가 (기존 `intensities`는 건드리지 않음)
- kmoni 수신 실패와 별개로 lmoni 실패는 헬스에 영향 주지 않음 (독립 추적)

### 3단계: 클라이언트 — 지도 표시 (src/)
- MapRenderer: `'lp-points'` maplibre 소스/레이어 추가 (intensity-points와 같은 circle 스타일, 계급색)
- 계급색: 장주기 계급 1~4 전용 색상 (진도색과 구별되는 보라~남색 계열, Legend에 항목 추가)
- 표시 조건: 계급 1 이상인 관측점만 점으로 표시 (평시에는 지도가 조용함)
- QuakeDetectService는 건드리지 않음 (장주기는 v1에서 감지 트리거 아님, 표시만)

### 4단계: 계급 배지 (App.tsx + i18n)
- 기존 `DataDelayBadge`처럼 지도 위 오버레이로 "장주기 최대 계급 N" 배지 — 계급 1 이상일 때만 표시
- 3개 언어 i18n 추가 (ko/en/ja)

### 5단계: 검증·배포
- `tsc`, `npm test`, 로컬에서 실제 lmoni 프레임으로 파싱 유닛테스트 추가
- `./deploy.sh` 배포 후 실서버 확인
- 실제 지진 발생 시 계급 표시가 나오는지는 자연 관찰

## 범위 밖 (이후 단계)
- 주기대(1~7s) 선택 UI, 장주기 기반 감지/디스코드 리포트 포함, 리플레이 저장
- lmoni 원본 다운타임 시 폴백 (지연 배지 헬스만 연결)

## 위험 요소와 대응
- 관측점 좌표가 kmoni GIF와 안 맞으면 → 레전드/실프레임 대조로 보정표 생성 (2단계에서 검증)
- lmoni 서버가 kmoni보다 부하에 민감할 수 있음 → 폴링은 1초 루프에 같이 넣되 실패해도 기존 감지에 영향 0, 과도한 재시도 없음
